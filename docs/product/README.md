## 번호 체계

```
1 ~ 53          기능 — 원본 표의 「번호」 열을 그대로 쓴다. 접두어를 붙이지 않는다
UC-04 ~ UC-10   유스케이스 (원본 「UC」 열에서 참조) ⚠️ 문서 없음
R1 ~ R7         위험 탐지 규칙 — 내용·심각도 정의됨. ⚠️ 상태(부적격/미제출) 매핑 없음
```

**요구사항 번호가 저장소의 공용어다.** Jira 이슈·브랜치·커밋·PR이 전부 이것을 가리킨다.

## 코드와 명세가 다르면

**임의로 정하지 않는다.** 명세가 의도이고 코드가 뒤처진 것인지, 코드가 현실이고 명세가 낡은 것인지는 그때그때 다르다.

한쪽을 조용히 다른 쪽에 맞추면 **결정이 기록되지 않고,** 다음 사람은 그것이 합의된 것인지 누가 임의로 정한 것인지 알 수 없다.

**팀에 묻고, 답이 늦으면 PR 본문에 적어 두고 넘어간다.**

## 보류 — 발전 가능성으로 남긴 것

**만들 수 있는데 안 만든 것만 여기 적는다.** 못 만든 것도, 안 하기로 한 것도 아니라 **순서가 뒤인 것**이다.

| 번호 | 지금 상태 | 완료 조건 (그때 이걸로 확인한다) |
| --- | --- | --- |
| **11번** 부품 엑셀 일괄 등록 (FE 전용) | 화면에 **버튼만** 있다. 누르면 「아직 준비 중」이라고 말한다 — 하는 일을 숨기지 않는다 | 「**오류가 하나라도 있으면 전체를 등록하지 않는다**」. **정상 9행 + 오류 1행을 올려 9행도 안 들어가는지** 본다. 행 단위 검증은 부품명 중복 · CN코드 8자리 숫자 · 단위 `KG\|TON\|EA` |

**팀이 우선순위를 낮게 두기로 했다** (이슈 [#15](../../../../issues/15)). API 가 필요 없는 FE 전용 기능이라 **BE 를 기다릴 것은 없다** — 여유가 생기면 위 완료 조건부터 만든다.

**여기 적힌 것은 이슈로 열려 있지 않다.** 열린 이슈는 「지금 막고 있는 것」만 두기로 했고, 순서가 뒤인 것은 이 표가 기억한다.
