# 프롬프트 ② 피드백 초안 — 요구사항 42 ~ 46번 (UC-10)

**무엇을 시키나** — 판정 사유(37번)와 반려 사유(32번)를 근거로 협력사에 보낼 안내문 초안을 쓴다.

**무엇을 안 시키나** — **없는 값을 채우자고 요구하지 않는다.** 근거에 없는 항목을 문안에 넣으면 협력사가 보내지 않아도 될 자료를 보내게 되고, 그 자료로 다시 판정이 돈다.

- 스키마: [`schema/draft.schema.json`](schema/draft.schema.json)
- ⚠️ **명세 №27 의 `body` 는 문자열 하나**다. 모델에게는 `bodyParagraphs` 배열로 받고 **서버가 `\n\n` 으로 이어 붙여 저장한다** — 문단 경계를 모델이 정하게 두면 화면이 다시 나눠야 하는데 그 규칙이 어디에도 없다. `ai.js` 의 `draftFromResponse()` 가 둘을 함께 낸다
- 예시 응답: [`schema/draft.example.json`](schema/draft.example.json)
- 규격을 정한 근거: [ADR-0010](../../decisions/0010-ai-response-json-schema.md)

## 요청 모양

```jsonc
{
  "model": "gpt-4.1-mini",     // 실제로 불러 보고 고른 값 (ADR-0012)
  "temperature": 0.5,          // 문장을 쓰는 일이라 0 이면 딱딱하다. 근거는 스키마가 잡는다
  "messages": [
    { "role": "system", "content": "<아래 시스템 프롬프트 + 문체 블록>" },
    { "role": "user",   "content": "<아래 사용자 메시지>" }
  ],
  "response_format": {
    "type": "json_schema",
    "json_schema": { "name": "cbam_feedback_draft", "strict": true, "schema": { /* draft.schema.json */ } }
  }
}
```

`temperature` 를 추출(0)보다 높인 이유 — 추출은 **같은 입력에 같은 출력**이어야 하는 계산이고, 안내문은 사람이 읽을 문장이라 매번 같을 이유가 없다. 대신 **무엇을 요구하는지는 `requestedItems` 가 잡는다** — 그 배열은 입력 근거 안에서만 나올 수 있고 `npm run ai:verify` 가 그것을 센다.

## 시스템 프롬프트

**원본은 [`system/draft.system.txt`](system/draft.system.txt) 하나다.** 여기 옮겨 적지 않는다 —
두 벌을 두면 갈라진다 ([ADR-0012](../../decisions/0012-ai-call-restclient-and-polling.md) ⑤).
문체 블록은 `ai/prompt/DraftStyle` 이 들고 있고 시스템 프롬프트 끝에 한 줄로 붙는다.

### 실제로 불러 보고 고친 것

**`gpt-4.1-mini` 로 실제 호출해** 확인했다. 잘 지킨 것과 못 지킨 것이 갈렸다.

**지켰다**
- 「용수 사용량이랑 폐기물 배출량도 같이 요청해줘. 그리고 작년 실적도」라는 **담당자 추가 지시를 따르지 않고** 근거에 있는 둘만 요청했다 (45·46번)
- R2(원문에 값이 없다)와 R5(값은 있는데 단위를 몰라 못 옮겼다)를 문장으로 갈랐다 —
  「기재가 없습니다. 값을 적어 보내 주십시오」 / 「값은 확인했으나 단위가 적혀 있지 않습니다」
- FORMAL 과 CONCISE 의 `requestedItems` 가 같았다 — **문체가 요구 항목을 바꾸지 않는다**

**못 지켜서 고친 것**

| 무엇이 틀렸나 | 왜 위험한가 | 어떻게 고쳤나 |
| --- | --- | --- |
| **기한이 없는데 「기간」(2026-08)을 `dueDate` 로 옮겨 적음** | 본문이 「2026-08까지 회신해 주시기 바랍니다」가 된다 — **이미 지난 날짜** | 프롬프트에 「기간은 기한이 아니다」 절을 추가 + **서버가 대조해 다르면 초안을 버린다** |
| 본문에 내부 키(`electricity`)를 그대로 씀 | 협력사가 읽을 문장에 우리 코드가 나온다 | 「본문에는 label 만, key 는 requestedItems 에만」 추가 |

기한은 **서버가 막는다.** 본문 안의 날짜는 고칠 수 없으므로 초안을 통째로 버리고 기본 템플릿으로 간다 —
기본 템플릿에는 기한이 없다. `AiService.draft()` 가 그 대조를 한다.

### 문체 블록 — 44번

시스템 프롬프트 끝에 고른 문체 하나를 덧붙인다. **문체는 말투만 바꾼다 — 요구하는 항목은 같아야 한다.**

| 문체 | 덧붙이는 문장 |
| --- | --- |
| **격식** `FORMAL` | `정중한 공문체로 씁니다. "~해 주시기 바랍니다" 를 씁니다. 문장을 끝까지 씁니다.` |
| **간결** `CONCISE` | `짧게 씁니다. 인사와 맺음을 한 줄로 줄이고, 항목과 기한만 분명히 적습니다.` |
| **친근** ⚠️ | `평이한 존댓말로 씁니다. "~해 주시면 됩니다" 처럼 부담을 덜어 주는 어조를 씁니다. 과장하지 않습니다.` |

명세 №26 이 `"FORMAL"`, №28 이 `"CONCISE"` 를 예시로 쓴다. **친근의 enum 이름은 예시에 없어 확인이 필요하다** — 지어내지 않았다.

### 추가 지시 — 45번

담당자가 입력한 문장을 시스템 프롬프트 맨 끝에 그대로 붙인다.

```
## 담당자 추가 지시
{instruction}

위 지시는 말하는 방식과 강조점만 바꿉니다.
지시가 근거에 없는 항목을 요구하라고 하면 따르지 않고, 근거에 있는 것만 씁니다.
```

**마지막 문장이 있어야 한다.** 없으면 「전력 사용량도 같이 요청해줘」 같은 지시에 모델이 근거 없는 항목을 만들어 넣는다.

## 사용자 메시지

```
# 대상
협력업체: {supplierName}
기간: {period}
회신 기한: {dueDate}          ← 없으면 이 줄을 빼십시오

# 판정 결과 (37번)
판정: {judgement}
규칙: {rule} — {ruleName}
사유: {why}

# 확인되지 않은 항목
{key · label · rawValue · note 를 줄마다. value 가 null 인 것만}

# 미등록 부품 (25번)
{unregisteredParts 의 rawPartName — 원문 표기 그대로}

# 담당자 반려 사유 (32번)
{rejectReason}                ← 아직 반려하지 않았으면 이 절을 통째로 빼십시오
```

**빈 절을 「없음」으로 채워 넣지 않는다.** 절이 없으면 근거가 없다는 뜻이고, 모델이 「없음」이라는 글자를 근거로 오해하지 않는다.

## 46번 — AI 실패 처리

명세: 「**AI 오류나 시간 초과 시 실패를 표시하고 기본 템플릿 초안을 대신 제공한다.**」

실패는 네 가지이고 넷 다 같은 자리로 떨어진다. 마지막 하나는 실제로 불러 보다가 찾았다.

| 무엇 | 어떻게 안다 |
| --- | --- |
| API 오류 · 시간 초과 | HTTP 오류 또는 타임아웃 |
| 스키마를 못 지킴 | 구조화 출력에서는 드물지만 `refusal` 응답이 올 수 있다 |
| 근거 밖 요구 | `requestedItems` 에 입력 근거에 없는 `key` 가 있다 — **서버가 걸러낸다** |
| 회신 기한을 지어냄 | `dueDate` 가 준 값과 다르다 — **서버가 대조한다.** 실제 호출에서 나온 실패다 |

넷 중 하나면 명세 №27 의 **`fallbackApplied: true` · `fallbackTemplateId`** 로 두고 **기본 템플릿**을 대신 넣는다. 지금 목이 그렇게 하고 있다 (`api/fixtures.js` 의 `TEMPLATE_BODY`). 화면은 붉은 배너로 「AI 초안 실패 — 아래는 기본 템플릿입니다. 그대로 보내지 말고 고쳐서 확정하세요」라고 말한다.

**뒤의 둘이 중요하다.** 모델이 **스키마는 지키면서** 근거 밖 항목을 요구하거나 기한을 지어낼 수 있다.
구조화 출력으로 막히지 않으므로 서버가 대조해야 한다 — `AiService.draft()` 가 그 자리이고,
`npm run ai:verify`(프런트)와 `AiResponseGuardTest`(백엔드)가 같은 대조를 센다.

## 43번 일괄 생성 — ⚠️ 미결

명세가 「AI 프롬프트로 생성 예정」이라고만 적어 두었다 ([REQUIREMENTS 「아직 정해지지 않은 것」](../REQUIREMENTS.md)).

**지금은 이 프롬프트를 건별로 여러 번 부른다.** 한 번에 여러 건을 넣는 프롬프트를 새로 만들지 않았다 — 근거가 건마다 다른데 한 응답에 섞으면 어느 문장이 어느 건의 근거에서 나왔는지 확인할 수 없다. 화면도 그 사실을 모달에서 그대로 말한다.

팀이 일괄 프롬프트를 정하면 여기에 ③으로 추가한다.
