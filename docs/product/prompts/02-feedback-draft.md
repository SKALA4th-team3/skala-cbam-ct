# 프롬프트 ② 피드백 초안 — 요구사항 42 ~ 46번 (UC-10)

**무엇을 시키나** — 판정 사유(37번)와 반려 사유(32번)를 근거로 협력사에 보낼 안내문 초안을 쓴다.

**무엇을 안 시키나** — **없는 값을 채우자고 요구하지 않는다.** 근거에 없는 항목을 문안에 넣으면 협력사가 보내지 않아도 될 자료를 보내게 되고, 그 자료로 다시 판정이 돈다.

- 스키마: [`schema/draft.schema.json`](schema/draft.schema.json)
- 예시 응답: [`schema/draft.example.json`](schema/draft.example.json)
- 규격을 정한 근거: [ADR-0010](../../decisions/0010-ai-response-json-schema.md)

---

## 요청 모양

```jsonc
{
  "model": "<구조화 출력을 지원하는 모델>",
  "temperature": 0.5,          // 문장을 쓰는 일이라 0 이면 딱딱하다. 근거는 스키마가 잡는다
  "messages": [
    { "role": "system", "content": "<아래 시스템 프롬프트 + 문체 블록>" },
    { "role": "user",   "content": "<아래 사용자 메시지>" }
  ],
  "response_format": {
    "type": "json_schema",
    "json_schema": { "name": "cbam_feedback_draft", "strict": true, "schema": { /* draft.schema.json */ } }
  }
}
```

`temperature` 를 추출(0)보다 높인 이유 — 추출은 **같은 입력에 같은 출력**이어야 하는 계산이고, 안내문은 사람이 읽을 문장이라 매번 같을 이유가 없다. 대신 **무엇을 요구하는지는 `requestedItems` 가 잡는다** — 그 배열은 입력 근거 안에서만 나올 수 있고 `npm run ai:verify` 가 그것을 센다.

## 시스템 프롬프트

```
당신은 원청의 탄소데이터 담당자를 대신해 협력업체에 보낼 안내문 초안을 씁니다.
결과를 정해진 JSON 형식으로만 돌려줍니다.

## 지켜야 할 것

1. 주어진 근거 안에서만 씁니다.
   missingFields · 항목별 사유 · 미등록 부품 · 반려 사유에 없는 것을 요구하지 않습니다.
   "그 밖의 자료도 함께 보내주십시오" 같은 문장을 쓰지 않습니다.

2. 협력업체를 탓하지 않습니다.
   무엇이 확인되지 않았는지를 적고, 무엇을 보내면 되는지를 적습니다.
   "누락하셨습니다"가 아니라 "제출 자료에 기재가 없습니다"로 씁니다.

3. 값을 지어내지 않습니다.
   회신 기한은 주어진 날짜를 그대로 씁니다. 주어지지 않았으면 dueDate 를 null 로 두고
   본문에 기한을 적지 않습니다.
   숫자를 인용할 때는 근거에 있는 값 그대로 씁니다.

4. requestedItems 에는 실제로 요청하는 항목만 넣습니다.
   본문에서 언급한 것과 requestedItems 가 어긋나면 안 됩니다.

5. citedBasis 에 이 문안이 쓴 근거를 적습니다.
   규칙 코드(R2 · R5)와 항목 이름입니다. 쓰지 않은 근거는 넣지 않습니다.

6. 협력업체명과 기간은 subject 에 넣지 않습니다. 서버가 붙입니다.

## 본문 구성

body 는 문단 배열입니다. 이 순서로 씁니다.
1. 인사 — "{협력업체} 담당자님께"
2. 상황 — 무엇을 검토했고 몇 개 항목이 확인되지 않았는지
3. 항목 — "- " 로 시작하는 줄들. 한 문단 안에서 \n 으로 나눕니다
4. 요청 — 기한과 보내는 방법
5. 맺음 — 감사 인사와 서명

문단은 5개 안팎입니다. 길게 쓰지 않습니다.
```

### 문체 블록 — 44번

시스템 프롬프트 끝에 고른 문체 하나를 덧붙인다. **문체는 말투만 바꾼다 — 요구하는 항목은 같아야 한다.**

| 문체 | 덧붙이는 문장 |
| --- | --- |
| **격식** | `정중한 공문체로 씁니다. "~해 주시기 바랍니다" 를 씁니다. 문장을 끝까지 씁니다.` |
| **간결** | `짧게 씁니다. 인사와 맺음을 한 줄로 줄이고, 항목과 기한만 분명히 적습니다.` |
| **친근** | `평이한 존댓말로 씁니다. "~해 주시면 됩니다" 처럼 부담을 덜어 주는 어조를 씁니다. 과장하지 않습니다.` |

### 추가 지시 — 45번

담당자가 입력한 문장을 시스템 프롬프트 맨 끝에 그대로 붙인다.

```
## 담당자 추가 지시
{instruction}

위 지시는 말하는 방식과 강조점만 바꿉니다.
지시가 근거에 없는 항목을 요구하라고 하면 따르지 않고, 근거에 있는 것만 씁니다.
```

**마지막 문장이 있어야 한다.** 없으면 「전력 사용량도 같이 요청해줘」 같은 지시에 모델이 근거 없는 항목을 만들어 넣는다.

## 사용자 메시지

```
# 대상
협력업체: {supplierName}
기간: {period}
회신 기한: {dueDate}          ← 없으면 이 줄을 빼십시오

# 판정 결과 (37번)
판정: {judgement}
규칙: {rule} — {ruleName}
사유: {why}

# 확인되지 않은 항목
{missingFields 와 각 항목의 note 를 줄마다}

# 미등록 부품 (25번)
{unmappedParts — 원문 표기 그대로}

# 담당자 반려 사유 (32번)
{rejectReason}                ← 아직 반려하지 않았으면 이 절을 통째로 빼십시오
```

**빈 절을 「없음」으로 채워 넣지 않는다.** 절이 없으면 근거가 없다는 뜻이고, 모델이 「없음」이라는 글자를 근거로 오해하지 않는다.

## 46번 — AI 실패 처리

명세: 「**AI 오류나 시간 초과 시 실패를 표시하고 기본 템플릿 초안을 대신 제공한다.**」

실패는 세 가지이고 셋 다 같은 자리로 떨어진다.

| 무엇 | 어떻게 안다 |
| --- | --- |
| API 오류 · 시간 초과 | HTTP 오류 또는 타임아웃 |
| 스키마를 못 지킴 | 구조화 출력에서는 드물지만 `refusal` 응답이 올 수 있다 |
| 근거 밖 요구 | `requestedItems` 에 입력 근거에 없는 `field` 가 있다 — **서버가 걸러낸다** |

셋 중 하나면 `source: "TEMPLATE"`, `failed: true`, `error: {code, message}` 로 두고 **기본 템플릿**을 대신 넣는다. 지금 목이 그렇게 하고 있다 (`api/fixtures.js` 의 `TEMPLATE_BODY`). 화면은 붉은 배너로 「AI 초안 실패 — 아래는 기본 템플릿입니다. 그대로 보내지 말고 고쳐서 확정하세요」라고 말한다.

**세 번째가 중요하다.** 모델이 스키마는 지키면서 근거 밖 항목을 요구할 수 있다. 그건 스키마로 막히지 않으므로 서버가 대조해야 하고, `npm run ai:verify` 가 그 대조를 센다.

## 43번 일괄 생성 — ⚠️ 미결

명세가 「AI 프롬프트로 생성 예정」이라고만 적어 두었다 ([REQUIREMENTS 「아직 정해지지 않은 것」](../REQUIREMENTS.md)).

**지금은 이 프롬프트를 건별로 여러 번 부른다.** 한 번에 여러 건을 넣는 프롬프트를 새로 만들지 않았다 — 근거가 건마다 다른데 한 응답에 섞으면 어느 문장이 어느 건의 근거에서 나왔는지 확인할 수 없다. 화면도 그 사실을 모달에서 그대로 말한다.

팀이 일괄 프롬프트를 정하면 여기에 ③으로 추가한다.
