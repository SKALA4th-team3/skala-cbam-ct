# ADR-0013: AI 는 `RestClient` 로 부르고, 화면 계약은 202 + 폴링으로 둔다

- 상태: 채택
- 날짜: 2026-09-04
- 관련 기능: 22 · 23 · 24 · 25 · 42 · 43 · 44 · 45 · 46번 · API 명세 v10 №19 · №26 · №28
- 근거: [`AI_WORKFLOW.md`](../AI_WORKFLOW.md) 4항 (**라이브러리 도입**) · [`application.yml`](../../backend/src/main/resources/application.yml) 의 「AI 호출은 스프링 표준 설정이 없다. **방식이 정해지면 ADR 을 쓰고 여기에 붙인다**」

## 배경

제공자가 OpenAI 로 정해졌고([ADR-0010](0010-ai-response-json-schema.md)), 응답 JSON 규격과 프롬프트는 [`docs/product/prompts/`](../product/prompts/) 에 있다. 남은 것은 **어떻게 부르는가**다.

Jira 하위 작업의 이름이 갈림길을 하나 만든다.

| | 이름 | 명세 |
| --- | --- | --- |
| CBAM-100 | 접수 메일 적격 여부 판단 API — **polling** | №26 계열과 같은 202 + `taskId` |
| CBAM-99 | 메일 초안 작성 API — **stream** | **№26 · №28 은 202 + `taskId`** 다. 스트림이 아니다 |

## 검토한 선택지

### 라이브러리

**A. `RestClient` 로 직접 부른다 (고른 것)** — Spring Boot 4.1.1 의 `spring-web` 에 이미 있다. 의존성이 늘지 않는다. OpenAI 요청은 JSON 한 덩어리이고 응답도 구조화 출력이라 SDK 가 해 줄 일이 거의 없다.

**B. OpenAI 공식 SDK** — 안 고른 이유: 의존성이 하나 늘고, 제공자가 바뀌면(수업 키가 만료되거나 팀이 다른 것을 고르면) 그 SDK 가 코드 전체에 박힌다. `RestClient` 면 URL 과 바디만 바꾸면 된다.

### 스트리밍

**A. 화면 계약은 202 + `taskId`, 스트리밍은 서버 안에서만 쓴다 (고른 것)**

- 장점 — **명세 №26 · №28 을 안 깬다.** 31건짜리 팀 계약을 한 자리만 다르게 만들지 않는다
- 장점 — **FE 를 안 고친다.** 지금 화면이 `latestAnalysisTaskId` 로 №19 를 폴링하는 구조로 이미 돌고 있다
- 장점 — 스트리밍의 실익은 그대로 얻는다. 첫 토큰까지가 짧아 **긴 응답에서 읽기 타임아웃이 덜 난다** — Jira 가 `stream` 이라 적은 이유가 그것으로 읽힌다
- 단점 — 담당자가 문장이 써지는 것을 실시간으로 보지는 못한다

**B. SSE 엔드포인트를 새로 낸다** — 안 고른 이유: **명세에 없는 32번째 엔드포인트**가 되고, 구조화 출력(`strict`)과 겹치면 화면이 **깨진 JSON 조각**을 받는다. 문단이 완성되기 전에 무엇을 그릴지 규칙이 어디에도 없다. 화면에 타자 효과가 필요하다고 팀이 정하면 그때 설계 파생으로 더한다 — 되돌리기 쉬운 쪽을 뒤로 미룬다

## 결정

**① `RestClient` 로 부른다.** 의존성을 더하지 않는다. 설정은 `cbam.ai.*` 로 모으고 `.env` 의 `AI_BASE_URL` · `AI_API_KEY` · `AI_MODEL` 을 읽는다.

**② 화면 계약은 202 + `taskId` + №19 폴링이다.** 스트리밍은 서버가 OpenAI 를 부를 때만 쓴다. 서버는 조각을 모아 완성된 JSON 을 검증한 뒤 저장한다 — **반쯤 만들어진 초안이 저장되는 길을 만들지 않는다.**

**③ 키가 없으면 앱이 뜬다.** `AI_API_KEY` 가 비면 AI 호출이 즉시 `AI_UNAVAILABLE` 로 실패하고 **46번의 기본 템플릿**으로 간다. dev 프로필과 테스트가 키 없이 돌아야 하기 때문이다. 지금 CBAM-88 이 이미 그 경로만으로 동작하고 있다.

**④ 실패는 №19 의 `errorCode` 로 말한다.** 명세가 정한 `AI_TIMEOUT` · `AI_ERROR` 를 쓰고 새 코드를 만들지 않는다. 작업이 실패해도 №19 는 **200 + `status: FAILED`** 다 (명세 №19 그대로). `fallbackApplied: true` 가 기본 템플릿으로 대체됐음을 말한다.

**⑤ 프롬프트와 스키마는 한 벌만 둔다.** `docs/product/prompts/schema/*.json` 이 원본이고, Gradle 이 빌드할 때 `backend` 의 리소스로 **복사한다.** 두 벌을 두면 갈라지고, 갈라지면 `ai:verify` 가 검사하는 것과 서버가 보내는 것이 달라진다.

## 결과

- 쉬워진다 — 제공자가 바뀌어도 `OpenAiClient` 한 파일이다
- 쉬워진다 — 화면·명세를 안 고치고 AI 를 꽂는다. FE 는 이미 폴링한다
- 쉬워진다 — 스키마가 한 벌이라 `npm run ai:verify` 가 검사한 그 파일을 서버가 그대로 보낸다
- **감수한다** — 실시간 타자 효과가 없다. 담당자는 「생성 중」을 보고 기다린다
- **감수한다** — 스트리밍을 서버 안에서만 쓰므로 그 이점(첫 토큰 지연)이 사용자에게 직접 보이지 않는다

## 다시 볼 조건

- **팀이 화면에 실시간 생성을 원하면** — 선택지 B 로 가고, 부분 JSON 을 화면이 어떻게 다룰지 함께 정한다 (문단 경계 규칙이 필요하다)
- 수업 키가 만료되거나 제공자가 바뀌면 — `cbam.ai.base-url` 과 `OpenAiClient` 를 본다
- 구조화 출력이 `strict` 를 지원하지 않는 모델만 남으면 — 응답 검증을 서버가 직접 해야 한다 (`ai-verify` 의 검증기를 Java 로 옮긴다)
