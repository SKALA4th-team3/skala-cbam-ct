# 기술 결정 기록

**되돌리기 어려운 선택**만 여기 적는다.

## 언제 쓰나

| 쓴다 | 안 쓴다 |
| --- | --- |
| DB 스키마 모양, 키 설계 | 컬럼 하나 추가 |
| **AI 응답 JSON 규격** | 프롬프트 문구 수정 |
| 라이브러리·프레임워크 도입 | 이미 정한 것의 버전 올리기 |
| 메일 수신 방식(IMAP/API), 폴링 주기 | 결함 수정 |
| **명세의 미결정 항목을 확정할 때** | 명세대로 구현 |

*3일 뒤에 누가 「왜 이렇게 했지?」라고 물을 것 같으면 쓴다.*

## 명세의 미결정 항목을 정하면 두 곳을 고친다

[`../product/REQUIREMENTS.md`](../product/REQUIREMENTS.md)에 **「아직 정해지지 않은 것」** 표가 있다.

정할 때는 **ADR을 쓰고, 그 표에서 해당 줄을 지운다.** 한쪽만 하면 다음 사람이 「아직 미결정」인 줄 알고 다시 논의한다.

## 규칙

- **구현하기 전에 쓴다**
- 실제로 고를 수 있었던 **후보를 최소 둘** 비교한다
- **고르지 않은 이유**를 반드시 남긴다 — 그게 이 문서의 값이다
- 번호는 `0001`부터. **브랜치를 만들기 직전에 최신 `dev`를 받아** 다음 번호를 확인한다

⚠️ **두 사람이 같은 번호를 집어도 git은 막아 주지 않는다.** 제목이 다르면 파일명도 달라서 **충돌 없이 둘 다 merge되고**, 나중에 `ADR-0003`이 두 개가 된다. 그래서 번호는 눈으로 확인해야 한다.

**실제로 두 번 일어났다.** `ADR-0003`이 둘([브랜치 이름](0003-branch-name-jira-key.md)·[DB 프로필](0004-database-profiles.md))이 됐고, 뒤에 `ADR-0004`(상태값 경계)를 딴 쪽과도 부딪혔다. 지금은 정리했다 — DB 프로필이 0004, 상태값 경계가 0005다. **아래 표가 유일한 기준이다.** 새 번호를 딸 때 이 표의 마지막 줄 다음 번호를 쓴다.
