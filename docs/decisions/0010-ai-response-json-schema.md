# ADR-0010: AI 응답 JSON 규격은 화면이 이미 읽는 모양에서 뽑는다

- 상태: 채택
- 날짜: 2026-09-04
- 관련 기능: 22 · 23 · 24 · 25번 자료 추출 · 42 ~ 46번 피드백 초안
- 근거: [`AI_WORKFLOW.md`](../AI_WORKFLOW.md) 4항 — 「스키마 모양, **AI 응답 JSON 규격**, 라이브러리 도입이면 `decisions/`에 **먼저** 쓴다」

## 배경

수업에서 받은 OpenAI API 키가 생겨 **제공자가 정해졌다.** 그런데 백엔드 `com/skala/cbam/ai/` 의 `AiService` · `AiContoller` · `AiRepository` 는 아직 빈 껍데기이고, `build.gradle` 에 AI 라이브러리가 없다. 즉 **AI 호출이 붙기 직전**이다.

지금 정하지 않으면 이렇게 된다 — BE 가 편한 모양으로 응답 규격을 만들고, FE 가 그것을 화면 모양으로 옮기는 변환 계층이 하나 더 생긴다. 그 계층은 **양쪽 어느 쪽도 소유하지 않아** 필드가 하나 늘 때마다 두 곳을 고쳐야 한다.

**FE 는 이미 AI 출력이 들어갈 자리를 다 갖고 있다.** 목이 그 모양으로 돌고 화면이 그것을 그린다.

| 화면이 읽는 것 | 어디서 | 명세 |
| --- | --- | --- |
| `rows[].{ field, raw, value, unit, note, tone }` | `RawStdPair.vue` — 원문·표준값을 나란히 | 30번 |
| `rows[].where` | 자료 변환 화면의 위치 표기 | 23번 「추출 근거」 |
| `unmappedParts[]` | 검토 화면의 미등록 부품 패널 | 25 · 27번 |
| `analysisFailed` · `failure{code,message}` | 분석 실패 배너 | 22번 |
| `body[]` 문단 배열 · `basis` | 초안 화면 좌우 2단 | 44번 |

## 검토한 선택지

### A. 화면이 읽는 모양을 스키마로 굳히고, 구조화 출력으로 강제한다 (고른 것)

- 장점 — **변환 계층이 생기지 않는다.** 모델 출력에서 화면 행까지 함수 하나(`rowsFromExtraction`)를 지난다
- 장점 — **호환성이 주장이 아니라 검사가 된다.** 예시 응답을 그 함수에 통과시켜 화면이 읽는 키가 다 나오는지 CI 가 센다
- 장점 — 「모르면 비운다」(24번)를 **스키마가 강제한다.** `value` 를 `["string","null"]` 로 두고 `note` 를 `required` 로 두면 문장이 아니라 구조가 막는다
- 단점 — 화면 모양이 바뀌면 스키마도 바뀐다. 화면은 BE 보다 자주 바뀐다
- 단점 — 구조화 출력의 `strict` 제약을 스키마가 지켜야 한다 (모든 객체 `additionalProperties:false`, 모든 속성 `required`)

### B. AI 응답 규격을 새로 짓고 FE·BE 가 각자 변환한다

- 장점 — 화면과 모델이 따로 움직인다. 화면이 바뀌어도 프롬프트는 그대로
- **고르지 않은 이유** — **소유자 없는 변환 계층이 생긴다.** 3일에 5명이 병렬로 가는데, 양쪽 다 「저쪽이 맞추겠지」 하는 자리를 만들면 그 자리에서 어긋난다
- **고르지 않은 이유** — 호환성을 **확인할 방법이 없다.** 「호환된다」가 문서의 주장으로만 남는다

### C. 자유 텍스트로 받고 서버가 파싱한다

- 장점 — 프롬프트가 짧다
- **고르지 않은 이유** — 규제 신고 데이터다. 파싱이 실패하면 **조용히 빈 값**이 되고, 그건 이 제품이 제일 피하려는 것이다 (명세를 관통하는 규칙: 「모르면 비우고 **사유를 남긴다**」). 사유 없이 비는 길을 만들지 않는다

## 결정

**AI 응답 JSON 규격 둘을 `docs/product/prompts/schema/` 에 두고, 화면이 읽는 모양에서 뽑는다.**

- [`extraction.schema.json`](../product/prompts/schema/extraction.schema.json) — 22 ~ 25번
- [`draft.schema.json`](../product/prompts/schema/draft.schema.json) — 42 ~ 45번

함께 정한 것 넷.

**① 스키마에 `judgement` · `severity` · `rule` 을 넣지 않는다.**
적격 판정(33~37번)은 규칙이지 AI 가 아니다. ±30%(34번)·50% 변동(35번)·누락 검사(33번)는 산수다. LLM 을 넣으면 같은 입력에 다른 판정이 나오고, 규제 신고에서 그건 되돌릴 수 없다. **스키마에 그 필드가 없다는 것이 그 결정의 표현이다.**

**② 추출은 `temperature: 0`, 초안은 `0.5`.**
추출은 같은 자료에 같은 값이 나와야 하는 계산이고, 안내문은 사람이 읽을 문장이다. 초안이 흔들려도 **무엇을 요구하는지는 `requestedItems` 가 잡는다.**

**③ 표시 상태(`tone`)는 모델이 정하지 않는다.**
값에서 끌어낸다 — `value===null` → `missing`, `unit===null` → `anomaly`(R5), `confidence<0.9` → `expiring`, 그 밖 `complete`. 같은 값에 같은 색이어야 한다.

**④ 검증기를 직접 쓴다. `ajv` 를 넣지 않는다.**
쓰는 스키마가 좁고(타입·enum·required·nullable 유니온), 이 저장소는 이미 「테스트 러너 없이 `vite --ssr` 로 묶어 node 로 돌린다」를 택했다. `scripts/ai-verify.mjs` 가 **스키마의 strict 규칙 · 예시의 스키마 적합 · 화면 변환 · 근거 밖 요구**를 센다. 스키마가 이 좁은 범위를 넘어가면 그때 `ajv` 를 넣는다.

## 결과

- 쉬워진다 — BE 는 스키마 파일을 그대로 `response_format` 에 넣고, 받은 JSON 을 그대로 저장한다. 옮겨 적을 것이 없다
- 쉬워진다 — 「기존 웹 구조와 호환되는가」를 `npm run ai:verify` 가 답한다. 문서가 아니라 검사다
- 쉬워진다 — 「모르면 비운다」가 프롬프트 문장이 아니라 스키마 제약이 된다. 프롬프트를 고쳐도 안 깨진다
- **감수한다** — 화면 모양이 바뀌면 스키마·예시·변환 함수 셋을 같이 고쳐야 한다. `ai:verify` 가 안 고친 것을 잡는다
- **감수한다** — `strict` 제약 때문에 스키마에 선택 속성을 못 쓴다. 전부 `required` 이고 없는 값은 `null` 이다

## 다시 볼 조건

- **BE 가 이 규격으로 못 만들겠다고 하면** — 그때 선택지 B 로 가고, 변환을 **어느 쪽이 소유하는지** 함께 정한다
- 스키마가 타입·enum·required·nullable 을 넘어서면 (`pattern`·`$ref`·깊은 `anyOf`) — 직접 쓴 검증기를 버리고 `ajv` 를 넣는다
- 43번 일괄 초안 프롬프트가 정해지면 — 스키마 셋째가 생긴다
- 「조치 3종」(`AI 작성 안내문`·`AI 재요청문`·`AI 확인 요청문`)이 44번 문체와 어떤 관계인지 정해지면 — `draft.schema.json` 에 축이 하나 는다
