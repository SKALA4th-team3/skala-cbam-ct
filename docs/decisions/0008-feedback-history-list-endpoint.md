# ADR-0008: 발송 이력 전체 조회 경로를 명세에 더한다 (`GET /feedback-histories`)

- 상태: 채택
- 날짜: 2026-09-03
- 관련 기능: 51번 발송 실패 건 확인 · 53번 발송 이력 조회 · 49번 발송 결과 기록
- 근거: 이슈 [#13](../../../../issues/13)

## 배경

API 명세 v10 №31 은 발송 이력을 **협력업체별로만** 정의한다.

```
GET /api/v1/suppliers/{supplierId}/feedback-histories?type&status&from&to
```

`supplierId` 가 경로 필수라 **협력업체를 고르지 않으면 아무것도 부를 수 없다.**

그런데 요구사항 두 개가 **전사 목록**을 요구한다.

| 번호 | 원문 |
| --- | --- |
| **51** | 발송 **실패 건**을 확인한다 |
| **53** | 발송 이력을 조회한다 |

「이번 달 발송 실패 전체」를 보려면 **협력업체 48곳을 하나씩 부르는 수밖에 없다.** 48번 요청해서 대부분 빈 배열을 받는다. 화면은 그것을 합쳐 정렬한다 — 실패 3건을 찾으려고 그렇게 한다.

**지금 정해야 한다.** FE 의 발송 관리 화면이 이미 전체 목록을 보여주고 있어서, 목을 걷어내는 순간 그 화면이 부를 것이 없다.

## 검토한 선택지

### A. 전체 조회 경로를 명세에 더한다 (고른 것)

```
GET /api/v1/feedback-histories?supplierId&type&status&from&to&page&size&sort
```

- 장점 — **51번·53번이 요구하는 것을 한 번에 부른다.** 「이번 달 실패 전체」가 `?status=FAILED&from=&to=` 한 요청이다
- 장점 — `supplierId` 를 **선택 파라미터**로 두면 №31 이 하던 일도 이 경로가 한다. 협력업체 상세 화면은 `?supplierId=3` 으로 부른다
- 장점 — 목록 응답 봉투·페이징·에러 규약을 그대로 따른다. 새로운 규칙이 없다
- 단점 — **설계 파생이 1건 늘어난다.** 명세 31건이 32건이 된다
- 단점 — **BE 가 만들어야 한다.** FE 혼자 닫을 수 없는 결정이다

### B. 발송 관리 화면을 협력업체 상세 안으로 옮긴다

- 장점 — 명세를 한 글자도 안 고친다. №31 그대로 쓴다
- **고르지 않은 이유** — **51번이 요구하는 화면이 사라진다.** 「발송 실패 건 확인」은 실패한 건을 **찾는** 일인데, 어느 협력사가 실패했는지 모르는 상태에서 48곳을 하나씩 열어 보게 된다. 요구사항과 정면으로 어긋난다

### C. 화면이 협력업체별로 48번 부르고 합친다

- 장점 — 명세도 BE 도 안 건드린다. 오늘 당장 된다
- **고르지 않은 이유** — 요청 48건 중 45건이 빈 배열이다. 협력사가 늘면 그만큼 늘어난다
- **고르지 않은 이유** — **정렬과 페이징을 화면이 다시 만들어야 한다.** 서버가 주는 봉투를 버리고 화면이 집계하는 구조가 되고, 그 숫자가 서버와 어긋나도 아무도 모른다

## 결정

**`GET /api/v1/feedback-histories` 를 명세에 더한다.** `supplierId` 는 **선택** 파라미터다.

- FE 는 이 경로를 지금 선언한다 (`Feedback.list`). 목이 그 계약대로 응답한다
- **№31 은 남긴다.** 협력업체 상세에서 그 업체의 이력만 볼 때 쓰는 경로다 — 명세에 이미 있고 BE 가 그것으로 구현 중일 수 있다
- **설계 파생 1건 증가**를 감수한다. 명세 31건 → 32건

**BE 가 이 경로를 만들어야 이 결정이 완성된다.** FE 는 그때까지 목으로 돈다 — `npm run api:status` 가 그 사실을 센다.

## 결과

- 쉬워진다 — 51번이 한 요청이 된다. 발송 관리 화면이 서버 필터(`status=FAILED`)를 그대로 쓴다
- 쉬워진다 — 협력업체 상세도 같은 경로를 `?supplierId=` 로 쓸 수 있다. 화면이 두 모양을 안 만든다
- **감수한다** — 명세에 없던 경로다. 설계 파생임을 `API-CONTRACT.md` 와 이 문서에 남긴다
- **감수한다** — BE 작업이 1건 늘어난다. 대신 48번 부르는 화면을 안 만든다

## 다시 볼 조건

- BE 가 **№31 만으로 가겠다고 하면** — 그때는 선택지 B 로 돌아가고, **51번을 어떻게 충족할지 함께 정해야 한다**
- 명세 원본에 이 경로가 반영되면 이 문서의 「설계 파생」 표기를 지운다
