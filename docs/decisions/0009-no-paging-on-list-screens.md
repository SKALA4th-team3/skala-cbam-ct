# ADR-0009: 목록 화면은 페이징하지 않는다 — 전량을 받아 브라우저에서 거른다

- 상태: 채택
- 날짜: 2026-09-03
- 관련 기능: 3번·4번 협력업체 목록 · 9번 부품 목록 · 11번 완제품 목록 · 29번 검토 대기 목록
- 근거: 이슈 [#20](../../../../issues/20)

## 배경

목록 화면 여섯 곳이 **전량을 받아 브라우저에서 필터·정렬한다.**

```js
rows.value = (await Suppliers.list({ size: 1000 })).content
```

`useTable` 이 그 배열로 **패싯 배지 숫자를 센다.** 「거래 상태 · 협력유지중 **46**」 같은 숫자다. 이 숫자는 **전체 기준이어야** 뜻이 있다 — 필터를 걸기 전에 「거기에 몇 개가 있나」를 보는 값이기 때문이다.

**서버가 페이지를 자르면 그 숫자가 조용히 틀린다.** 20건만 받으면 배지는 20건 안에서 센 숫자가 되고, 화면은 일부만 받은 사실을 모른다. **틀렸다는 신호가 어디에도 안 난다** — 그래서 지금 정해 둔다.

## 검토한 선택지

### A. 전량 조회를 유지하고, 「페이징하지 않는다」를 명시한다 (고른 것)

- 장점 — **규모가 그렇다.** 협력사 48곳 · 부품 수십 개 · 완제품 10여 개 · 검토 대기 10건 안쪽이다. 한 번에 받아도 수십 KB다
- 장점 — 필터·정렬·배지가 **한 곳(`useTable`)에** 있다. 화면 여섯 곳이 같은 규칙으로 돈다
- 장점 — **배지 숫자를 위한 집계 API 가 필요 없다.** 명세에 그런 API 가 없다
- 단점 — 데이터가 커지면 못 쓴다. 협력사가 수천 곳이 되면 처음부터 다시 만든다
- 단점 — **BE 가 이 약속을 모르면 페이지를 자른다.** 그래서 명시가 결정의 절반이다

### B. 필터·정렬을 서버로 옮긴다

- 장점 — 명세의 쿼리 파라미터를 그대로 쓴다 (`?search&country&status&submissionStatus&page&size&sort`). 규모와 무관하게 옳다
- **고르지 않은 이유** — **패싯 배지 숫자를 서버가 따로 내려줘야 한다.** 「이 조건에서 각 값이 몇 개인가」를 주는 API 가 명세에 없다. 새 API 를 정의하고 BE 가 만들어야 한다
- **고르지 않은 이유** — 화면 여섯 곳과 `useTable` 을 다시 쓴다. 3일에 그 값이 아니다. **지금 막고 있는 것도 아니다** — 48곳은 한 화면에 다 들어온다

## 결정

**협력업체·부품·완제품·검토 대기·접수함·발송 이력 목록은 페이징하지 않는다.** 서버는 전량을 돌려주고, 필터·정렬·배지는 브라우저가 계산한다.

- **`API-CONTRACT.md` 에 적는다** — BE 가 페이지를 자르지 않게. 이 문서가 그 근거다
- **잘리면 드러나게 해 뒀다.** `api/index.js` 의 `allRows(res, where)` 가 `totalElements > content.length` 를 보고 개발 콘솔에 경고한다

```
[API] GET /suppliers: 48건 중 20건만 받았다.
      화면이 브라우저에서 필터하므로 배지 숫자와 목록이 전체를 반영하지 않는다
```

**이 경고가 뜨면 그때가 선택지 B 로 옮길 때다.** 고친 것이 아니라 **드러나게 한 것**이다 — 조용히 틀리는 것만 막았다.

## 결과

- 쉬워진다 — 화면이 하나의 필터 규칙만 안다. 서버는 목록 하나만 만들면 된다
- 쉬워진다 — 배지 숫자가 언제나 전체 기준이다. 집계 API 를 안 만든다
- **감수한다** — 데이터가 커지면 이 결정이 깨진다. 깨질 때 **소리가 나게** 해 뒀다
- **감수한다** — 목록 응답의 `page`·`size`·`totalPages` 를 화면이 안 쓴다. 봉투는 규약대로 유지한다 (규약 4항)

## 실서버 확인 (2026-09-04)

**BE 는 `size` 를 100 까지만 받는다** — `?size=1000` 에 `400 size 는 100 이하여야 합니다` 를 준다. 「서버가 전량을 준다」는 이 결정과 어긋나는 상한이다.

**협력사 48곳은 한 번에 들어온다.** 부품·완제품이 100개를 넘으면 그때부터 잘리고, `allRows()` 가 경고한다. **상한을 올릴지 필터를 서버로 옮길지는 그 경고가 뜰 때 정한다** — 지금 막고 있지 않다.

## 다시 볼 조건

- **`allRows()` 경고가 개발 콘솔에 뜨면** — 서버가 자르기 시작했다는 뜻이다
- **`size` 상한 100 에 걸리면** — 부품이 100개를 넘는 순간이다
- 협력사가 수백 곳이 되거나, 검토 대기가 한 화면을 넘어가면
- 패싯 배지를 서버가 내려주는 집계 API 가 명세에 생기면
