# ADR-0001: 이상치 판정을 ±30% 고정으로 한다

- 상태: 채택
- 날짜: 2026-09-03
- 관련 기능: 34번 평균값 비교 · R4 평균값 대비 이상치

> **2026-09-03 재확인 — IQR 은 채택하지 않는다.** API 명세 v10 이 №21 변경사유·추적표 비고에 「IQR 채택 여부 확정 필요」를 미결로 남겨 두어 이 문서와 어긋나 있었다. 팀에 물어 **±30% 유지·IQR 미채택**으로 답을 받았다 (이슈 [#11](../../../../issues/11)). **이 문서가 기준이고, API 명세의 미결 표기가 낡은 것이다** — 명세 원본을 가진 사람이 그 두 곳을 정정한다.

## 배경

34번은 「허용 범위(**예: ±30%, 설정값**)를 벗어나면 이상치」라고만 하고, 원본 「비고」에 **「IQR?」** 한 마디가 붙어 있었다. 무엇으로 재는지가 안 정해진 상태였다.

**지금 정해야 한다.** 36번이 이 결과로 심각도를 부여하고, 29번 검토 목록의 기본 정렬과 40번 심각도별 건수가 그 심각도를 쓴다. 기준이 없으면 **핵심 줄(18 → … → 33·36 → 29 → 31 → 41)이 판정 단계에서 임의값 위에 올라간다.**

## 검토한 선택지

### A. 동일 품목 평균값 ±30% 고정 (고른 것)

- 장점 — 팀의 위험 탐지 규칙에서 **R4가 이미 「동일 품목 평균값 ± 30% 초과」로 못 박혀 있다.** 화면·규칙 코드·명세가 한 값을 가리킨다
- 장점 — 표본이 한 건만 있어도 판정이 나온다
- 장점 — 34번이 「설정값」이라고 했으므로 상수를 코드에 박지 않고 뺄 수 있다
- 단점 — 품목마다 분산이 다른 것을 무시한다. 원래 편차가 큰 품목에서 오탐이 난다

### B. IQR (사분위수 범위)

- 장점 — 품목별 분포에 맞춰 경계가 자동으로 잡힌다. 임계값을 사람이 안 고른다
- **고르지 않은 이유** — **R4와 어긋난다.** 규칙 화면이 ±30%라고 말하는데 코드가 IQR로 재면, 담당자가 화면에서 본 기준과 판정 결과가 달라진다
- **고르지 않은 이유** — IQR은 사분위수를 낼 만큼 표본이 있어야 한다. **확정 데이터는 31번을 통과한 것만 쌓이는데** 개발 기간이 3일이다. 품목당 몇 건으로 낸 사분위수는 경계가 아니라 잡음이다

## 결정

**동일 품목 평균값 ±30%를 벗어나면 이상치(R4, MEDIUM)로 표시한다.** ±30%는 **설정값**으로 두고 코드에 상수로 박지 않는다 — 34번이 「설정값」이라고 명시한다.

## 결과

- 쉬워진다 — 표본이 적어도 판정이 나온다. 화면(R4)·명세(34번)·코드가 같은 값을 가리킨다
- **감수한다** — 품목별 분산 차이를 못 잡는다. 편차가 원래 큰 품목에서 오탐이 나면 담당자가 30번 상세에서 원본 값을 보고 거른다
- 35번(이전 기간 대비 50% 변동, R7)도 같은 모양의 **설정값**이다. 둘을 같은 자리에 둔다

## 다시 볼 조건

- 동일 품목 확정 데이터가 분포를 볼 만큼 쌓이고, **±30%가 실제로 오탐·미탐을 낸다는 것이 관찰되면**
- 팀이 R4 규칙 자체를 바꾸면 — **R4가 기준이고 이 문서가 따라간다**
