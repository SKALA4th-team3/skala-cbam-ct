# ADR-0003: 브랜치 이름을 Jira 이슈 키 하나로 한다

- 상태: 채택
- 날짜: 2026-09-03
- 관련 기능: 전체 (작업 방식)

## 배경

지금까지 브랜치 이름은 `feat/be/24-unit-normalize` — `{type}/{domain}/{feature}` 였다. **손으로 만드는 형식이다.**

그런데 우리는 Jira 이슈에서 **「브랜치 만들기」로 바로 브랜치를 딴다.** 이 대화상자는 `CBAM-43-이슈제목` 을 채워 주고, 기존 형식을 쓰려면 **매번 그것을 지우고 `feat/be/24-unit-normalize` 를 다시 타이핑해야 한다.** 5명 × 53개 기능이면 그 타이핑이 53번이고, 그중 몇 번은 오타가 난다.

**브랜치 이름을 만드는 곳이 터미널에서 Jira로 옮겨 갔다.** 이름 형식도 그 자리에 맞춰야 한다.

되돌리기 어렵다 — 한 번 섞이면 `git branch -a` 에 두 형식이 같이 남고, 어느 쪽이 맞는지 아무도 모른다.

## 검토한 선택지

### A. 이슈 키 하나 — `CBAM-43` (고른 것)

- 장점 — Jira 대화상자에서 **뒷부분만 지우면 끝난다.** 손으로 다시 쓰는 글자가 없다
- 장점 — 브랜치명에 키가 있으니 **브랜치를 만든 순간부터** Jira ↔ GitHub 연동이 붙는다. 이슈 화면에 브랜치·커밋·PR이 자동으로 모인다
- 장점 — 오타가 날 자리가 없다. **키 한 글자가 틀리면 연동이 통째로 안 붙는데**, 손으로 안 쓰면 틀릴 일이 없다
- **단점 — `git branch -a` 만 봐서는 type·도메인·요구사항 번호를 알 수 없다.** 이게 이 결정의 값이다 (아래 「결과」)

### B. 키 + 번호 + 기능명 — `CBAM-43-24-unit-normalize`

- 장점 — 키와 요구사항 번호가 **둘 다** 브랜치명에 남는다
- **고르지 않은 이유** — 결국 **매번 뒷부분을 타이핑한다.** A가 없앤 문제를 그대로 두면서 이름만 길어진다. 게다가 `43` 과 `24` 두 숫자가 나란히 붙어 **어느 쪽이 요구사항 번호인지 헷갈린다**

### C. 기존 형식 유지 + 키를 끼워 넣기 — `feat/be/CBAM-43-24-unit-normalize`

- 장점 — 소유 범위(`be`/`fe`)가 브랜치명에 그대로 남는다
- **고르지 않은 이유** — Jira 기본값과 가장 멀다. **대화상자에서 전부 다시 쓴다.** 그럴 거면 Jira에서 만들 이유가 없다

## 결정

**브랜치 이름은 Jira 이슈 키 하나다** — `CBAM-43`.

- 브랜치는 **Jira 이슈 화면의 「브랜치 만들기」로 만든다.** 터미널에서 손으로 만들지 않는다
- 대화상자가 채워 주는 나머지는 **앞뒤 모두 지운다** — 뒤의 이슈 제목(`CBAM-43-...`)도, 앞의 종류(`feature/CBAM-33`)도.
  둘 다 실제로 나온 적이 있다
- **원본 브랜치는 `dev`.** 기본값이 `main` 이면 바꾼다
- **커밋 형식은 하나도 바꾸지 않는다** — `[BE] Feat: CBAM-12 24번 …` 그대로다

## 결과

**쉬워지는 것** — 브랜치를 만드는 데 타이핑이 없다. 이슈 화면에서 그 이슈의 브랜치·커밋·PR을 한 번에 본다.

**어려워지는 것 — 감수하기로 한 것이다.** `git branch -a` 가 이제 `CBAM-43` 만 보여 준다. **누가 어느 요구사항 번호를, 어느 영역(be/fe)을 잡고 있는지 브랜치 목록만 봐서는 모른다.** 그건 원래 「한 브랜치 = 한 Task = 한 PR」 을 지키는 장치였다.

**그 역할을 보드로 옮긴다.**

| 브랜치명에서 사라진 것 | 어디서 보나 |
| --- | --- |
| `feat` `fix` … | Jira 이슈 타입 · 커밋 제목의 `Feat:` |
| `be` `fe` `etc` | Jira 컴포넌트/라벨 `BE`·`FE`·`ETC` · 커밋 접두어 `[BE]` |
| `24번` | **Jira 이슈 제목이 「24번 …」으로 시작한다** · 커밋 제목의 `24번` |

그래서 **두 가지가 전보다 중요해졌다.**

1. **이슈 제목은 반드시 요구사항 번호로 시작한다** — 키와 번호를 잇는 자리가 이제 여기뿐이다
2. **이슈에 컴포넌트/라벨 `BE`·`FE`·`ETC` 를 반드시 단다** — 소유 범위를 아는 자리가 이제 여기뿐이다

**겹침 확인은 `git branch -a` 가 아니라 보드에서 한다.**

## 다시 볼 조건

- Jira ↔ GitHub 연동을 걷어내거나 브랜치를 Jira 밖에서 만들게 되면 — 키만 남는 이름의 이득이 사라진다
- 보드에 이슈 제목의 번호나 컴포넌트가 자주 빠져서, 브랜치가 무슨 작업인지 추적이 안 되기 시작하면
