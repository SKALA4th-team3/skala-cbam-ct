# AI 작업 절차

**무엇을 만드는가가 아니라 어떤 순서로 일하는가**를 정한다. [`AGENTS.md`](../AGENTS.md)를 먼저 읽는다.

---

## 1. 명세에서 F 번호를 찾는다

[`product/REQUIREMENTS.md`](product/REQUIREMENTS.md)에서 이 작업이 **F-01~F-53 중 어느 것인지** 찾는다.

**못 찾으면 코드를 쓰지 않는다.** 팀에 먼저 묻는다.

찾았으면 **기능 설명 문단을 통째로 복사해 둔다.** 요약하면 조건이 사라진다 — 대부분의 조건은 「~인 경우에만」, 「~하면 전체를」 같은 **막는 쪽**에 있고 그게 요약에서 제일 먼저 없어진다.

## 2. AI에게 맥락을 준다

새 대화마다 **매번** 준다.

1. **F 번호 + 기능 설명 원문** (1단계에서 복사한 것)
2. **명세의 「상태값」 표** — 안 주면 `ACTIVE`/`PENDING`을 지어낸다. 명세는 `협력유지중`·`검토 대기`를 쓴다
3. 관련된 **기존 코드 위치**와 API 계약

## 3. 계획을 먼저 받는다

**코드를 바로 받지 않는다.** 「어떤 파일을 어떻게 바꿀지」를 먼저 받는다.

- [ ] 명세에 없는 것을 스스로 정하지 않았는가
- [ ] 미결정 항목(정렬 기준, IQR, R1~R7)을 채워 넣지 않았는가
- [ ] 남의 영역(`be`/`fe`) 파일을 건드리지 않는가

**하나라도 걸리면 멈추고 묻는다.**

## 4. 되돌리기 어려운 선택이면 ADR을 먼저 쓴다

스키마 모양, AI 응답 JSON 규격, 라이브러리 도입이면 [`decisions/`](decisions/README.md)에 **먼저** 쓴다. 만들고 나서 쓰면 이미 그 선택을 정당화하게 된다.

## 5. 구현

작은 단위로 받고 **매번 읽는다.** 설명하지 못하는 코드가 쌓이면 리뷰에서도 설명하지 못한다.

## 6. 검증 — 세 층

| | 확인 |
| --- | --- |
| **돈다** | 빌드·테스트 통과 |
| **맞다** | **막는 쪽이 막히는지** 화면에서 눈으로 |
| **막는다** | 검사를 넣었으면 **되돌려서 실제로 실패하는지** |

### 「막는 쪽」이 무슨 뜻인가

되는 것만 확인하면 **절반만 확인한 것이다.**

| 기능 | 되는 것 | **막는 것 ← 이것도 본다** |
| --- | --- | --- |
| F-01 | 협력업체가 등록된다 | **같은 사업자번호·이메일이 거부되는가** |
| F-06 | 협력끊김으로 바뀐다 | **미제출 경보에서 빠지는가. 기존 데이터가 남아 있는가** |
| F-07 | 부품이 등록된다 | **CN코드 7자리·9자리가 거부되는가** |
| F-11 | 엑셀이 등록된다 | **1행만 틀려도 전체가 안 들어가는가** |
| F-18 | 메일이 접수된다 | **같은 Message-ID가 두 번 안 들어가는가** |
| F-31 | 적격 건이 확정된다 | **부적격·미등록부품 건이 확정 안 되는가** |
| F-35 | 변동이 감지된다 | **이전 데이터가 없으면 건너뛰는가** |
| F-41 | 합계가 나온다 | **미확정 부품 포함 완제품이 따로 표시되는가** |

### AI 관련은 실패 경로를 먼저 본다

**성공 경로는 데모에서 저절로 확인된다. 실패 경로는 안 보면 영영 안 본다.**

| 기능 | 넣어 볼 것 |
| --- | --- |
| **F-24** | 단위를 알 수 없는 값 → **비우고 사유가 남는가.** 그럴듯하게 채우면 실패 |
| **F-22** | 암호 걸린 xlsx → **「분석 실패」로 기록되고 담당자에게 알리는가** |
| **F-20** | 첨부 없는 메일 / `.hwp` → **「접수 불가」** |
| **F-19** | 등록 안 된 주소에서 온 메일 → **「미확인」** |
| **F-25** | 명세에 없는 품명 → **「미등록 부품」** |
| **F-46** | AI 응답 지연·오류 → **기본 템플릿 초안이 나오는가** |

**F-30이 최종 확인이다** — 표준화 값과 원본 값이 **나란히** 보이는가. 원본을 안 남겼으면 이 화면을 만들 수 없다.

## 7. PR

템플릿을 채운다. **「확인하지 못한 것」을 비워 두지 않는다.**

커밋과 PR에 **F 번호**를 남긴다.

## 8. 완료 체크리스트

- [ ] F 번호를 커밋과 PR에 적었다
- [ ] 기능 설명의 **조건문(막는 쪽)** 을 화면에서 확인했다
- [ ] 명세의 **상태값 이름**을 그대로 썼다
- [ ] 미결정 항목을 임의로 확정하지 않았다
- [ ] 확인하지 못한 것을 PR에 적었다
- [ ] Jira 이슈를 **완료**로 옮겼다
- [ ] 설명하지 못하는 코드가 남아 있지 않다
