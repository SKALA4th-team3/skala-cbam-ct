# FE ↔ BE 계약 — 기준 문서는 「CBAM API 명세서 v10」이다

**이 파일은 계약서가 아니다.** 계약은 팀이 만든 **CBAM_API명세서_v10** (엔드포인트 31건)이고,
여기에는 **FE 코드가 그 명세와 어긋나는 자리**만 적는다. 명세가 바뀌면 이 파일이 아니라 코드를 고친다.

이전 버전(FE 가 화면을 만들며 임의로 적어 둔 초안)은 폐기했다.

---

## 코드는 명세를 따른다

| | |
| --- | --- |
| Base | `/api/v1` — `VITE_API_BASE` |
| 목록 응답 | `content` · `page`(0부터) · `size` · `totalElements` · `totalPages` |
| 에러 | `{ timestamp, status, code, message, path, details }` · 사유마다 다른 `code` |
| 부분 수정 | **PATCH** (PUT 안 씀) · 상태 전이는 **POST** |
| 담당자 | `X-Operator-Id` 헤더 — **인증이 아니라 감사 기록용** |

엔드포인트 현황은 `npm run api:status` 로 센다. **21건이 명세와 같은 경로·메서드로 선언돼 있고 전부 목이다.**

---

## 아직 어긋나는 것 — 팀이 정해야 한다

### 1. 상태값이 한글과 영문 enum으로 갈린다

요구사항 명세는 **한글 상태값을 그대로 쓰라**고 하고(`협력유지중`·`적격`·`미제출`),
API 명세는 **영문 enum**(`ACTIVE`·`QUALIFIED`·`NOT_SUBMITTED`)을 내려준다.

지금 FE 목은 한글을 그대로 들고 있다. **실서버를 붙이는 순간 화면 필터가 전부 빈 목록이 된다.**
변환은 `api/index.js` 한 곳에서 한다 — BE 응답을 화면 표시값으로 바꾸는 매핑이 필요하다.

### 2. 협력업체 정렬 기준 (요구사항 №4)

요구사항이 **미결**이고 API 명세도 미결로 남겼다. 명세가 허용하는 sort 키는 `companyName`·`lastSubmittedAt` 뿐인데,
**화면은 「심각도 높은 순」을 기본으로 쓰고 있다.** 심각도는 협력업체의 속성이 아니라 제출 데이터에서 파생된다.

### 3. 발송 이력 조회가 협력업체별만 있다 (API №31)

명세는 `GET /suppliers/{supplierId}/feedback-histories` 뿐인데,
**발송 관리 화면은 전체 목록을 보여준다.** 전체 조회 경로가 없다.

### 4. 이상치 임계값 — 저장소 결정과 명세가 어긋난다

[ADR-0001](../docs/decisions/0001-outlier-threshold.md) 에서 **±30% 고정으로 이미 닫았는데**,
API 명세는 아직 「IQR 채택 여부 확정 필요」로 열어 두었다. 명세 쪽을 ADR 대로 닫으면 된다.

### 5. 부품 엑셀 일괄 등록 (요구사항 №11)

API 가 없는 **FE 전용** 기능이다. 화면이 행 단위로 검증해 **오류가 하나도 없을 때만** `POST /parts` 를 부른다.
지금 화면에는 버튼만 있고 검증도 업로드도 없다.
